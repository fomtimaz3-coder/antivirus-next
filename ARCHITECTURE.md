# Архитектурная проверка Anti-wiew 3.3.0

## Устройство проекта

Это статическое HTML/CSS/ES-module приложение с одной серверной функцией Vercel, а не Next.js. `index.html` и `app.js` управляют интерфейсом, очередью и IndexedDB. `scheduler.js` ограничивает число отдельных `worker.js`; каждый воркер вычисляет потоковый SHA-256, запрашивает репутацию через главный поток, запускает YARA и структурные анализаторы. `build-info.js` задаёт единую версию приложения и отчётов.

| Участок | Модули | Граница ответственности |
|---|---|---|
| Интерфейс и очередь | app, controls, ui-logic, report-view | Выбор файлов, настройки, отмена, сохранение и отображение результатов |
| Сканирование | worker, sha256, bloom, scheduler | Локальные байты, точное совпадение хеша после Bloom, управление нагрузкой |
| Контейнеры | containers, archive | ZIP / TAR / GZIP, общий бюджет, рекурсия, CRC/заголовки, APK-манифест |
| Статический анализ | static-analysis, macho | Ограниченные DEX/PE/ELF/Mach-O и текстовые признаки скриптов |
| Сигнатуры | yara, yara-runner, native/yara-wrapper.c, vendor | Изолированная WASM-проверка, таймауты; новый движок компилируется CI |
| Обновление правил | rule-store, bounded-read, scripts/update-rules.py | Публичные правила Malpedia, SHA-256 целостности, кеш и загрузка по платформе |
| Репутация | reputation, api/reputation.mjs | По согласию: только хеш и личный ключ через фиксированные адреса VT / MalwareBazaar |
| Офлайн и CI | sw, .github/workflows | Версионированный кеш UI; тесты, сборка WASM, обновление правил |

Файлы не передаются серверному API и не исполняются. Ключи находятся в памяти страницы; API получает ключ и хеш, пересылает соответствующему провайдеру. Код не записывает ключи в отчёты или хранилище. Репутация хранится отдельно с TTL шесть часов. Отчёты и настройки хранятся локально в IndexedDB.

## Исправлено в этой проверке

| Ошибка | Исправление / проверка |
|---|---|
| Universal Mach-O пропускал энтропию секций | Расчёт относительно начала каждой архитектуры; регрессия FAT с исполняемой секцией |
| Хеш-база пропускала вложения глубже первого ZIP | Сопоставление в общем callback каждой извлечённой записи; регрессия ZIP → ZIP → файл |
| Повреждение позднего каталога теряло предыдущие находки | Возврат частичного архива с накопленными результатами; тесты повреждённых ZIP и TAR |
| TAR.GZ оставался непросмотренным | Реализованы ограниченные TAR / GZIP, общий обход вложений; реальный YARA обнаруживает EICAR внутри TAR.GZ |
| Отключение репутации не отменяло fetch | AbortController для сканирований и диагностики; отмена ожидания очереди, запрет поздней записи в кеш |
| Блокировка IndexedDB могла остановить старт / запрос | Ограничено время ожидания открытия хранилища, предусмотрена работа без сохранения |
| Ответ VT не проверялся на соответствие хешу | Проверка id; несовпадение — ошибка, нулевые счётчики — unknown |
| Кеш правил мог оставаться старым при коротких сессиях | Проверка возраста на старте; периодическое обновление сохранено |
| Ограничение загрузки правил срабатывало после выделения памяти | Чтение потоком с лимитами: 256 КиБ манифест, 2 МиБ файл правил |
| Добавление файлов могло пересекаться с отменой / другой загрузкой | Последовательное добавление и поколение отмены; один снимок правил на подборку |
| Итог очереди оставался в состоянии ожидания оценки | Отдельные сообщения о завершении и пропусках |
| Видимое значение фильтра расходилось с применённым | Синхронизация собственного select при переходе в историю |
| Ручной режим потоков не сохранялся | Сохранение и восстановление настройки |
| Удалённый отчёт оставался в очереди / открытом диалоге | Удаление ссылок из очереди и текущего просмотра |
| Версии UI и воркера расходились | Общий build-info.js |
| Сетевой HTTP-сбой обходил офлайн-резерв правил | Неуспешный HTTP-ответ тоже включает кешированный резерв |
| Проверки CI запускались только с обновлением правил | Отдельный workflow на push main и pull request |

## Что проверено

`npm test`: существующие SHA-256/YARA/ZIP/APK/DEX/PE/ELF/Mach-O, категории отчётов и планировщик; новые сценарии TAR/GZIP, лимит распаковки, повреждённые каталоги с сохранением находок, вложенное совпадение хеша, ограничение HTTP-ответа, отмена fetch, нормализация VirusTotal. Нативный YARA запускается над безвредными тестовыми данными; API-провайдеры в регрессиях подменены тестовыми ответами.

## Незавершённые отдельные возможности и ограничения

Это не полная антивирусная защита Android. Ни отсутствие совпадений, ни неизвестный хеш не доказывают безопасность. Браузер не видит всю ОС, другие приложения и общую загрузку RAM.

- ClamAV CVD/CLD, OLE/VBA-макросы, криптографическая проверка APK, третий провайдер Hybrid Analysis, карантин и сервер обратной связи не реализованы. Они не выдаются за доступные проверки. Это отдельные функции, а не закрытые этой проверкой ошибки.
- Реальные образцы VirusShare не тестировались: доступ к набору не предоставлен. Подготовленный corpus-test требует контролируемого локального набора и известных хешей. EICAR не измеряет качество обнаружения настоящего вредоносного ПО.
- TAR: только обычные записи; PAX/GNU-расширения, ссылки и специальные типы пропускаются. GZIP: до 32 МиБ распакованного потока. Общие пределы: 500 записей, 128 МиБ распакованных байтов, 32 МиБ на запись, коэффициент 200×, два вложенных уровня. Каждый контейнер, включая GZIP, занимает уровень.
- YARA: 32 МиБ на файл, 15 секунд на вызов. Дополнительные правила имеют межвызовный бюджет 60 секунд; текущая операция может закончиться позже. Optional native modules не включены. Повторная компиляция правил на каждом вызове остаётся ограничением производительности.
- Анализаторы не исполняют код: DEX — ссылки на методы, PE/ELF — ограниченные таблицы, Mach-O — команды и секции. Энтропия Universal Mach-O рассчитывается отдельно для каждой архитектуры. Скрипты — текстовые признаки, не полный AST. Исходники Kotlin/C++ не имеют специализированного анализа.
- Обновления закрытой вкладки не гарантируются. SHA-256 проверяет целостность относительно манифеста, но не заменяет подпись издателя. Доверие опирается на HTTPS и репозиторий.
- Частота API ограничивается в пределах одной вкладки, не аккаунта / нескольких устройств. Ключи пользователя и реальная квота требуют отдельной проверки владельцем.
- Основной адрес Vercel пока связан с проектом mobile-desktop; код хранится в отдельном репозитории antivirus-next. Создание нового Vercel-проекта ранее было недоступно интеграции.

## Оптимизация 3.3.1

Один YARA-воркер и WASM instance живут до конца сканирования внешнего файла, включая вложения. Запросы сериализованы; сбой или таймаут уничтожает instance, следующий запрос создаёт новый. По завершении сканирования ресурсы освобождаются. Компиляция правил внутри aw_scan пока выполняется при каждом вызове.

До 128 успешных результатов YARA кешируются по SHA-256 внутри одного задания с неизменным снимком правил. Ошибки не кешируются. Распаковка, CRC, хеширование, анализ структуры с учётом имени и сопоставление хеш-базы выполняются для каждой записи; пути всех находок сохранены. Кеш не используется между заданиями и версиями правил.

Микрозамер на 30 небольших файлах с тремя штатными наборами правил: создание WASM каждый раз — 602 мс, переиспользование — 83 мс. Это замер из тестового окружения, не прогноз времени на Android или всего архива. Регрессии проверяют реальный постоянный WASM-воркер, одинаковые результаты, конкурирующие запросы, восстановление после ошибки и дубликаты EICAR с разными путями.
